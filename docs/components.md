# The component system

The clone's UI is one component set on the brand tokens, organised in four tiers under `src/components/`. This is the reference for it: the tiers and the rules, the map of every primitive and pattern with its live evidence, how to add a component, the live UI the clone does not render yet, and the decisions the sweep left to the design owner. Written 2026-09-07 at the end of the component system sweep (`docs/plans/2026-09-07-component-system-sweep.md`), extended 2026-09-10 for the `flow` primitive and the teams fleet (`docs/plans/2026-09-10-teams-fleet-v1.md`), and updated 2026-09-11 for the teams polish (`docs/plans/2026-09-11-teams-fleet-polish.md`); `src/components/components.test.ts` keeps the rules true.

## 1. Tiers and rules

| Tier | Path | What lives there |
|---|---|---|
| Primitives | `src/components/ui/` | 31 shadcn-style primitives on the brand tokens (pills, tints, hairlines, glass shadows) behind the phase-1 variant and size API, so page layouts keep their metrics, plus `flow`, the React Flow canvas, and `border-beam`, the animated edge (both new UI, not cloned). The only place `radix-ui`, `cmdk`, `@xyflow/react` and `border-beam` are imported. Every one carries a `data-slot` (the name the live site emits, where it emits one). |
| Patterns | `src/components/patterns/` | Composites of primitives used by two or more pages with the same intent: `PageHeading`, `SearchInput`, `EmptyState`, `ShowArchivedSwitch`. A pattern earns its file only when a shape recurs; a single use stays in the page. |
| Shell | `src/components/app/`, `src/components/composer/` | The sidebar, the frame, the account and section menus, the ⌘K palette, the composer and its menus. Built from the primitives; shell-local composites (the sidebar group header, the rail tooltip) stay in the shell. |
| Pages | `src/components/<page>/` and the routes in `src/app/(app)/` | Layout, data wiring and composition of the tiers above. Never a raw control. |

The rules, each locked by its own `it` in `src/components/components.test.ts` (`npm test`):

1. `radix-ui`, `cmdk` and `@xyflow/react` are imported only by files under `src/components/ui/` (React Flow has its own `it`). A page that needs a radix part gets it through a primitive; if no primitive wraps it yet, add one (§3). React Flow comes in through `ui/flow.tsx` alone, which re-exports the types and hooks a view needs (`Node`, `NodeProps`, `useReactFlow`, `useNodesState` …). The `border-beam` package comes in through `ui/border-beam.tsx` alone (its own `it`), which is where it learns the app theme.
2. No raw `<button>`, `<input>`, `<textarea>`, `<select>` or `<label>` in JSX under `src/components/**` (outside `ui/`) or `src/app/**`. The one allowed shape is the rendered element of an `asChild` primitive, where the raw tag is the primitive's direct child: `src/components/thread/option-cards.tsx` renders `<Card asChild size="none"><button …>` because the card itself is the pressable element. The test also allow-lists `src/app/design/brand/page.tsx`, whose three raw buttons are the motion specimens of the swatch page (press, hover and focus on a bare element), not controls the app ships.
3. `src/design/brand/ui/` does not exist and nothing imports `@/design/brand/ui` or `@/design/brand/utils`. The prototype's verbatim component copies were retired in the sweep and stay in git history.
4. Every `data-slot="<name>"` value in `docs/reference/pages/*.html` and `docs/reference/overlays/*.html` has a `data-slot="<name>"` under `src/components/ui/` or `src/components/patterns/` (57 values today, all defined). The assertion message lists any missing name, so a new capture that introduces a slot fails the suite until a primitive names it.
5. Every file under `src/components/ui/` contains at least one `data-slot=`.

Conventions every primitive follows (copy them in a new one): `data-slot` on the root and on every named part; a cva `variants` object where there are two or more looks, mirrored as `data-variant` / `data-size`; `cn()` last so `className` is the escape hatch; `asChild` through `Slot.Root` where a link or list item can be the element; Tabler icons with `aria-hidden="true"`; motion as `transition-[…] duration-(--duration-fast) ease-out-quart` with `motion-safe:active:scale-(--scale-press)`; fills as tints, edges as `shadow-edge` or `border-border-subtle`; no raw colours (`npm run brand:lint-tokens`).

### Brand artwork (`src/components/brand/`)

Not one of the four tiers: this folder holds the brand's artwork as React SVG (the mark in `mark.tsx`, its motion variants in `logo-motion/`, and since 2026-09-15 the agent glyphs). Pages and patterns compose it the way they compose a primitive. The tier rules still hold here (no raw control, nothing from radix, cmdk or React Flow), and, like the mark, it sits outside the Tabler rule because it is artwork, not an icon. ### Teams fleet (`src/components/teams/`)

Each surface says one thing and puts the rest one interaction deeper: a hover or focus reveal in space already reserved for it, a tooltip, or the sheet. The context holds:

- `team`, `agents`, `allRuns`: the mock, never filtered (the toolbar's count, the board's queue order, the org chart and the sheet read these).
- `runs` and `runsByStatus` (every status present, possibly empty): filtered by `query`, which matches a run's title, id or project or its agent's name or role.

`src/lib/motion.ts` is the JS mirror of the brand motion tokens for `motion/react`: `DURATION` in seconds, `EASE` as bezier arrays, `LAYOUT_TRANSITION` (220ms on ease-out-layout). Change it with `brand.css`; `/teams` sits in `MotionConfig reducedMotion="user"`.

**The store and the loop.** `SceneStore` keeps every character's position in tiles, as floats, and runs one `requestAnimationFrame` loop that advances walkers (linear, 6 tiles a second), swaps sprite frames and moves the chrome, all by writing `transform`, `z-index` and `background-position` through refs. React never renders per frame: a character's tile, facing, seat and motion are committed to an immutable snapshot (`useSyncExternalStore`) only when they change. Under reduced motion a step jumps, a click-to-walk teleports and every cycle holds one frame.

**One stacking context.** The map box holds the canvas, the furniture sprites and the characters as siblings, and every sprite's `z-index` is the bottom edge, in px, of the tile row it stands on (`Furniture.z * scale` for a piece, `(tile.y + 1) * TILE * scale` for a character; a chair sits 1 under its sitter), so characters pass in front of and behind desks and plants. That is why `FurnitureLayer` returns a fragment: never wrap it, or the characters, in a positioned element of their own. Sprites are drawn as the upstream sprite pack draws them, bottom-centre on the tile's centre, seated 6 art px lower.

**The chrome layer** sits over all of it (`z-index` 20000), at its natural size in the same px space (`px = tile * TILE * scale`): each tag, bubble or card hangs from a zero-size point the loop moves (`store.follow`). Tags wear the ink Tooltip's colours and are hidden from assistive tech, because each character's name already says what is drawn around it ("Echo, Email copywriter, working, needs you: Approve sending 42 emails, Outbound"). The Needs you bubble is the view's only tangerine. Every tag and bubble marks itself `data-obstacle`, and the ask card hangs where it covers none of them. The layer comes first in the DOM, so the ask card is the map's first tab stop.

**The four views are also on the marketing page.** `/landing/d`'s views band (`src/components/landing-v2/d/team-views.tsx`) renders `BoardView`, `ListView`, `OrgView` and `SpaceView` in one fixed-height panel behind a `Tabs` pill row, over a sixteen-run slice of the same mock, so the page shows the product rather than a drawing of it. It also hands `FleetProvider` a `team` whose owner is the page's own fictional person rather than the mock's, which signs the repo's author in: right on /teams, where the visitor is that account, and somebody else's name on a stranger's screen anywhere else. The view area there is `inert` and `pointer-events-none`: a picture, not the product. That is what the two opt-out props above are for, and it is also what keeps the agent sheet from portalling over a marketing page and the org chart from eating the page's scroll. The org chart and the office arrive as their own chunks (`next/dynamic`), so a reader who never opens those tabs pays for neither React Flow nor the sprite sheets.

## 3. How to add a component

1. `npx shadcn@latest add <name> --yes`. The file lands in `src/components/ui/` (`components.json`). If shadcn has no such component (the sweep hand-wrote `overline`, `icon-tile` and `nav-item`), write a 20-to-50-line file in the same shape: `data-slot`, a cva `variants` object, `cn()` last, `asChild` where it makes sense.
2. Convert the icons: the CLI emits `lucide-react`; rename each to its Tabler name per `docs/brand/icons.md` and add `aria-hidden="true"`. `npm test` rejects a lucide import.
3. Fix the `cn` import if the CLI wrote `from "cn"` or another wrong path: it must be `import { cn } from "@/lib/utils"`.
4. Re-skin on the brand strings: read "The brand in ten lines" in `docs/brand/reskin-conventions.md` and the neighbouring primitives, then replace shadcn's classes with the tints, hairlines, pills, radii and motion tokens. Take the class string from a route that already renders the shape when one exists (the sweep's `select.tsx` came from `/library`, `checkbox.tsx` from `/memories`).
5. Keep the `data-slot` names shadcn emits (they are the ones the live site emits) and keep the phase-1 heights (28 / 32 / 36 / 40) so nothing moves.
6. Run `npx tsc --noEmit`, `npm run lint`, `npm run brand:lint-tokens` and `npm test` (the slot lock and the raw-control rule), then the screenshot diff: capture the affected routes before and after with `scripts/dev/screenshot-pages.mjs` and compare pixel by pixel (the capture is deterministic, so any differing pixel is a real change).
7. Add a row to the map above.

## 5. Decisions left to the design owner, and the one pixel change

Two inconsistencies the audit found were left as they are because fixing them moves pixels, and the sweep's contract was zero pixel change:

- **Toolbar buttons and pressed chips** (audit §6.7). The 36px toolbar buttons are spelled four ways: threads `size="sm"` plus `h-9 gap-2`, memories `size="sm"` plus `h-9` (the 6px gap), agents `size="sm"` plus `h-9 shrink-0 gap-2`, skills the default size plus `h-9 gap-2` (16px padding, 12px beside an icon, so the skills Filters button is 2px wider than the threads one). The pressed filter chips use two tint strengths: threads `bg-tint-20`, library and the sidebar `bg-tint-15` lifting to `bg-tint-20` on hover. A `size="toolbar"` on `Button` and one pressed style on `outline` / `ghost` would unify them; each moves a metric or a tint step on one page.
- **Glass fills on hover-revealed actions** (audit §6.12). Three glass looks for one idea: the home thread card's actions (`bg-background/80 backdrop-blur-sm` on an outline icon button), the threads card's actions (`bg-surface-elevated/80 shadow-edge backdrop-blur-sm` on a ghost icon button) and the thread view's scroll-to-bottom pill (`bg-surface-elevated/90 shadow-md ring-1 ring-border-subtle backdrop-blur-sm`). One glass variant would unify them and move a fill on one of the two lists.

The one deliberate pixel change the sweep made: the sidebar group headers Agents and Recent threads now render the brand's 12px caps role like Resources. Before the sweep they were sentence case by accident: the browser's button stylesheet reset `text-transform` on the raw `<button>` before the caps role applied. Commit "fix(shell): caps on every sidebar group header" (`572a136`); it touches the sidebar on every route, so every route differs from the pre-sweep baseline in exactly those two labels.
